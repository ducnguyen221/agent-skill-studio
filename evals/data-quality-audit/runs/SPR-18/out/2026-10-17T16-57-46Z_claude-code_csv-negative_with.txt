`CALCULATE` evaluates an expression after you change the filter context it runs in. It is the main way to control filtering in DAX.

**Syntax**

```
CALCULATE( <expression>, <filter1>, <filter2>, ... )
```

- `<expression>` is usually a measure or aggregation, such as `SUM(Sales[Amount])`.
- Each filter modifies the filter context for that expression only.

**Filter context**

Every DAX measure is evaluated inside a filter context. This is the set of filters from slicers, visual axes, rows and columns of a matrix, and relationships. A "Total Sales" measure in a cell for *Region = West, Year = 2025* sums only the rows matching those two filters.

`CALCULATE` lets you rewrite that context before the expression is computed. You can add filters, replace existing ones, or remove them.

**What the filter arguments do**

| Filter type | Effect | Example idea |
|---|---|---|
| Boolean/column filter | Overrides any existing filter on that column | `Product[Color] = "Red"` |
| Table filter (`FILTER(...)`) | Applies a row-by-row condition, so it can involve measures or several columns | `FILTER(Sales, Sales[Qty] > 5)` |
| Modifier (`ALL`, `REMOVEFILTERS`, `KEEPFILTERS`, `USERELATIONSHIP`) | Clears or preserves filters, or switches relationships | `ALL(Date)` for an all-time total |

**Behaviours to know**

1. **Overwrite by default.** A filter on a column replaces any existing filter on that same column. Use `KEEPFILTERS` if you want to intersect instead.
2. **Multiple filters combine with AND.**
3. **Context transition.** Inside a row context, such as a calculated column or an iterator like `SUMX`, `CALCULATE` turns the current row into an equivalent filter context. This is why wrapping a measure in `CALCULATE` inside `SUMX` works. It is also the most confusing part of DAX.
4. **Evaluation order.** The filter arguments are evaluated first, in the original context. The expression is then evaluated in the new context.

**Typical uses**

- Compare against a fixed slice, such as "sales for Red products only".
- Compute percent of total by removing filters (`ALL`) in the denominator.
- Time intelligence. Functions like `SAMEPERIODLASTYEAR` and `DATESYTD` are filter-producing functions that you pass into `CALCULATE`.
- Activate an inactive relationship with `USERELATIONSHIP`.

**Analogy**

Think of a camera with a view restricted by a mask (the filter context). `CALCULATE` swaps the mask, then takes the measurement. Everything outside the new mask is ignored.
